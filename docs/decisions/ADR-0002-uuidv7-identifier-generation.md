# ADR-0002: UUIDv7 Identifier Generation

- Status: accepted
- Date: 2026-08-30
- Related findings or requirements: ADR-0001, IMPLEMENTATION_GUIDE section 3.1

## Context

Guarded Agent identifiers must be opaque, sortable, validated at every boundary, and generated by a maintained UUID or ULID implementation. The bootstrap package used Node's `randomUUID()`, which emits UUIDv4 values and therefore does not satisfy the sortable-identifier contract. Implementing UUIDv7 entropy, timestamp, and monotonic sequencing locally would add security-sensitive format code unrelated to the project thesis.

The dependency policy permits one narrow maintained UUID/ULID generator after an exact-version, lifecycle-script, license, transitive-dependency, and boundary review.

## Decision

Use exact-pinned `uuid@14.0.2` inside `@guard/contracts` and generate UUIDv7 values behind the package's prefixed branded-ID constructors. Boundary parsers require the correct prefix, lowercase canonical UUID syntax, and UUID version 7. `ErrorId` uses the same format and validator.

The package is used only for identifier generation and validation. It does not enter policy, runtime orchestration, persistence, capability, provider, or sandbox code.

Dependency review:

- Purpose: maintained UUIDv7 generation and validation.
- License: MIT.
- Runtime dependencies: none in the installed package manifest.
- Lifecycle and binary review: the published manifest declares development-oriented `prepare`, `prepack`, and `prepublishOnly` hooks; registry installation used the prebuilt package without running a dependency install hook, and the package downloads no native binary.
- Exact version: `14.0.2`, recorded in `package-lock.json`.
- Removal difficulty: low because all calls remain behind `@guard/contracts` constructors.

## Alternatives Considered

- Keep UUIDv4: rejected because it contradicts the accepted sortable-ID contract.
- Implement UUIDv7 locally: rejected because monotonic state, entropy, clock behavior, and canonical validation are avoidable correctness risks.
- Use a ULID package: technically valid, but UUIDv7 preserves the existing UUID-shaped external representation and has maintained support in the selected narrow package.

## Consequences

Persisted IDs use `<kind>_<lowercase-uuidv7>`. Changing the representation after persisted events exist will require an explicit migration and compatibility decision. Dependency upgrades require lockfile review and identifier conformance tests. Lexicographic order is suitable for operational locality but never replaces event stream version or database-recorded ordering.
